====================================================
本地发布订阅通信模拟器（教学版）· 使用说明
配套课时：《信息科技》八年级上册 第1单元 第4节 物联网的通信
====================================================

一、运行方法
1. 需要 Python 3.8 及以上（自带 tkinter 和 socket，无需安装任何第三方库，
   也不需要 paho-mqtt）。
2. 在本文件夹中打开终端执行：
       python3 本地发布订阅通信模拟器.py
   Windows 下可执行：python 本地发布订阅通信模拟器.py
3. 无界面逻辑自测（验证 Topic 匹配与转发逻辑，不弹窗）：
       python3 本地发布订阅通信模拟器.py --selftest

二、功能与操作步骤
1. 点【▶ 启动中转站】：程序在本机 127.0.0.1（默认端口 18830）启动一个
   极简"消息中转站"（相当于教材中 MQTT 的服务器/代理 broker）。
2. 添加订阅者：在右侧输入名称与订阅 Topic，点【➕ 添加订阅者】。
   可添加多个订阅者，每个有自己独立的消息窗口。支持通配符：
       +  匹配恰好一层，如 farm/+/temp 能匹配 farm/sensor/temp
       #  匹配末尾所有层，如 farm/# 能匹配 farm 下的一切主题
3. 发布消息：在发布者面板填写 Topic 和内容，点【📤 发布这条消息】；
   或勾选【自动发布】，程序每 2 秒轮流向 farm/sensor/temp 和
   farm/sensor/humi 发送一条随机的虚拟温度/土壤湿度数据。
4. 观察：中转站日志区会显示 连接/订阅/发布/转发 全过程（不同颜色）；
   只有 Topic 匹配的订阅者才会收到消息——这正是发布/订阅机制的核心。
5. 导出：顶部按钮可把全部日志导出为 JSON 或 CSV（UTF-8）。文件夹中的
   "示例数据_发布订阅日志.csv" 展示了导出格式。
6. 停止：点【■ 停止中转站】或直接关闭窗口，程序会优雅关闭所有
   socket 连接与线程。

三、教学协议格式（每行一条命令，UTF-8，字段用 | 分隔）
   NAME|昵称               客户端报到，登记显示名
   SUB|farm/sensor/temp    订阅主题（支持 + 与 #）
   UNSUB|主题              退订
   PUB|主题|内容           发布消息
   服务器 → 订阅者：MSG|主题|内容

四、为什么说这是"模拟"而不是真实 MQTT（教学说明）
1. 真实 MQTT 是国际标准的二进制协议，报文头最小仅 2 字节（教材数据：
   3G 网络下吞吐量比 HTTP 快 93 倍）；本工具为了让同学们能直接"读懂"
   每一条报文，改用了人类可读的文本协议。
2. 真实 MQTT 还包含 QoS（服务质量等级）、保留消息、遗嘱消息、心跳保活、
   用户认证等机制，本工具只保留了最核心的思想：
   客户端只与服务器连接，发布者与订阅者互不相识，
   只要"发送和订阅的是同一个主题（Topic）"，即可相互沟通。
3. 本工具仅绑定本机回环地址 127.0.0.1，不访问互联网、不扫描网络、
   不连接任何真实设备，所有设备名与 Topic 均为虚构教学示例。
4. 如果以后想体验真实 MQTT：可在教师指导下使用 paho-mqtt 库连接
   教师搭建的 MQTT 服务器（对应教材"智能农植园数据的发送"活动）。

五、常见问题排查
1. 启动失败提示端口被占用：把端口改成其他值（如 18831）再启动。
2. 【添加订阅者】【发布】没反应：请先启动中转站。
3. 订阅者收不到消息：
   · 检查发布 Topic 与订阅模式是否匹配（+ 只顶替一层，层数必须相等；
     # 只能放在模式末尾）；
   · 检查是否把消息发到了别的 Topic（看中转站日志里的"匹配 0 个订阅者"）。
4. 防火墙弹窗询问：本程序只在本机内部通信，可放心允许或拒绝外网访问。
5. 提示找不到 tkinter：Linux 下执行 sudo apt install python3-tk 后重试。
